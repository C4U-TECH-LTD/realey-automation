Realey Automation - E2E Test Framework

Git Repo: https://github.com/C4U-TECH-LTD/realey-automation

Workflow runs: https://github.com/C4U-TECH-LTD/realey-automation/actions

Allure Report: https://c4u-tech-ltd.github.io/realey-automation/#behaviors

Scope1: https://docs.google.com/document/d/1PGPuQkOIPVuXW8TupFHK1oHrzti7RAQjKoxI1HfLDsM/edit?tab=t.0

Automated End-to-End (E2E) testing framework for the Realey platform built using Playwright, Cucumber.js (BDD), and Allure Reports.

1. Flow Overview

Each automation flow represents a complete, self-contained business journey.

  • Independent: Every flow creates its own listing dynamically.
  • No Dependencies: Flows operate in isolated browser contexts and do not depend on each other.
  • Sequential Execution: When run together, flows execute sequentially to prevent server rate limits and protect local hardware resources.

2. Quick Start Guide (Local)

Prerequisites

  • Node.js: v20 or v24+
  • Browser: Google Chrome or Chromium

Setup

git clone https://github.com/C4U-TECH-LTD/realey-automation.git
cd realey-automation
npm install
npx playwright install --with-deps chromium

Environment Variables:

Copy .env.example to .env and populate it with required credentials (e.g., BASE_URL, Stripe test cards).

Running Tests

  • Run a single flow: npm run test:flow-1 (or npx cucumber-js --tags "@flow-1")
  • Run all flows: npm run test:all-flows (Auto-discovers all flows tagged with @all-flows)

3. Reporting

Reports are automatically generated during test runs.

  • Local HTML Report: Run npm run report:generate followed by npm run report:open.
  • Live Dashboard: https://c4u-tech-ltd.github.io/realey-automation/#suites
  • Artifacts: Screenshots are saved in screenshots/cucumber/ and session videos in videos/cucumber/.

4. Project Structure (Key Folders)

The framework follows the Page Object Model (POM) and BDD architecture.

  • features/e2e/: Contains sequentially numbered feature files (e.g., 01-fixed-price.feature). Add new flows here.
  • pages/: Page Object classes (UI locators and actions).
  • features/step-definitions/: Cucumber step definitions mapping Gherkin to code.
  • reports/ & allure-report/: Test results and compiled dashboards.

5. Adding a New Flow

  • Create Feature File: Add XX-flow-name.feature to features/e2e/.
  • Tag It: Use tags @e2e @all-flows @flow-N.
  • Implement: Add required UI locators to pages/ and step logic to step-definitions/.
  • Execute: The suite will automatically pick it up in npm run test:all-flows, or you can run it directly via its tag.

Critical End-to-End Flows

In addition to module-level automation, the following end-to-end business-critical workflows (1-9) and checks are included in Phase 1.

Flow 1 – Fixed Price: Direct Offer Acceptance & Settlement Completion
Agent Login → Create Fixed Price Listing → Buyer Login → View Listing → Submit Offer → Agent Accepts Offer → Buyer Starts Settlement → Add Buyer Solicitor → Add Buyer Broker → Pay Deposit Fee → Complete Settlement
Flow 2 – Offer Price: Counter Offer Negotiation & Settlement Completion
Agent Login → Create Offer Price Listing → Buyer Login → View Listing → Submit Offer → Agent Sends Counter Offer → Buyer Negotiates Counter Offer → Agent Accepts Counter Offer → Buyer Starts Settlement → Add Buyer Solicitor → Add Buyer Broker → Pay Deposit Fee → Complete Settlement
Flow 3 – Auction: Reserve Price Met & Settlement Completion
Agent Login → Create Auction Listing → Buyer Login → Select Auction Property → Register as Bidder → Place Bid → Auction Ends → Reserve Price Met → Buyer Starts Settlement → Pay Deposit Fee → Add Buyer Solicitor → Add Buyer Broker → Complete Settlement
Flow 4 – Auction: Reserve Price Not Met, Counter Offer Accepted & Settlement Completion
Agent Login → Create Auction Listing → Buyer Login → Select Auction Property → Register as Bidder → Place Bid → Auction Ends → Reserve Price Not Met → Agent Negotiates With Registered Bidder → Buyer Negotiates Counter Price → Agent Accepts Counter Price → Buyer Starts Settlement → Pay Deposit Fee → Add Buyer Solicitor → Add Buyer Broker → Complete Settlement
Flow 5 – Auction: Reserve Price Not Met, Counter Offer Rejected & Property Re-listed
Agent Login → Create Auction Listing → Buyer Login → Select Auction Property → Register as Bidder → Place Bid → Auction Ends → Reserve Price Not Met → Agent Negotiates With Registered Bidder → Buyer Negotiates Counter Price → Agent Rejects Counter Price → Agent Re-lists Property as Fixed Price / Auction
Flow 6 – Property Sale: Settlement to Exchange, Document Signing & Settlement Date Confirmation
Agent Login → Create Listing → Buyer Login → Submit Offer/Place Bid → Agent Accepts → Buyer Starts Settlement → Add Buyer Solicitor → Add Buyer Broker → Pay Deposit Fee → Complete Settlement → Agent Marks "Ready for Exchange" → Seller Solicitor Initiates Exchange → Buyer Solicitor Assigns Buyer for Signing → Buyer Signs Documents → Buyer Solicitor Passes Documents to Seller Solicitor → Agent Adds Vendor → Seller Solicitor Passes Documents to Vendor → Vendor Signs Documents → Seller Solicitor Proposes Settlement Date → Buyer Solicitor Accepts Settlement Date → All Relevant Parties Receive Notification → Settlement Date Added to Calendar
Flow 7 Sales Instructions — Auto-Send After Settlement Completion
Agent Login → Create Listing → Buyer Submits Offer → Agent Accepts → Buyer Starts Settlement → Add Buyer Solicitor → Add Buyer Broker → Pay Deposit Fee → Complete Settlement → Agent Navigates to Settlements Tab → Agent Clicks “Sales Instructions” → Verify Auto-Sent to Broker, Seller Solicitor, and Buyer Solicitor
  • Confirmed delivery channels: chatroom message, email, AND in-app notification — all three fire simultaneously, test all three
  • Confirmed timing: the button is not clickable/visible before the 5-step settlement process is complete — include a negative-path assertion for this
  • Confirmed idempotency: clicking “Sales Instructions” a second time silently does nothing — no resend, no error message. Test this explicitly, not just the happy path
  • Recipients should be exactly Broker, Seller Solicitor, and Buyer Solicitor — confirm Buyer and Vendor do NOT receive it
  • This is also the right flow to assert Firm, Agent Licence No., and Agency Licence No. fields populate correctly on the generated document rather than blank — see Section 2 (module corrections)
Flow 8 Buyer Task Visibility — Correct Trigger Point Restriction
Agent Login → Create Fixed Price Listing → Seller Solicitor Configure Progress → Buyer Submits Offer → Agent Sends Counter offer → Buyer Views Chatroom → Verify Configure Progress Task List Is NOT Visible or Interactive → Buyer Accepts Counter Offer → Verify Progress Task List Automatically Appears in the Chatroom
Flow 9 Passed-In Auction — Negotiation Declined (No Counter-Offer)
Agent Login → Create Auction Listing → Buyer Registers and Bids → Auction Ends, Reserve Not Met → Agent Attempts to Negotiate With Highest Bidder → Highest Bidder Declines to Negotiate → Verify Agent Can Move to Next-Highest Genuine Bidder
